## What is new in 1.1.14

SquirrelOps Home 1.1.14 is a substantial reliability, deception, alerting, and
installer release.

### More coherent fake hosts

- Squirrel Scouts now builds one fake host per eligible real source device.
- Every observed port gets its own service-decoy record and protocol-specific
  behavior, while services copied from the same source share one virtual IP and
  hostname.
- Full mode supports up to 30 active fake hosts. The limit is a ceiling, so
  Scouts does not create duplicate copies of the same source merely to fill it.
- Fake-host names are editable. A rename updates the entire shared-IP group and
  persists across app and sensor restarts.
- Virtual IP allocation verifies that an address is free and no longer leaves
  undeployable `0.0.0.0` records.
- HTTPS fake hosts use persistent synthetic certificates. HTTP behavior,
  service banners, and mDNS advertisements are scoped to the observed service.

### Better alerts with complete evidence

- High and Critical prompts now offer **Review** and **Clear**. Review opens the
  Alerts panel without marking the batch read. Clear acknowledges only the
  presented batch.
- Connections from one source across several decoy ports are coalesced into one
  active port-scan alert instead of flooding the database and dashboard.
- Every connection is still retained in the forensic connection log.
- Credential attempts on supported HTTP Basic, form, JSON, and chunked request
  paths produce Critical alerts without a redundant High alert.
- Ordinary Bonjour and IPP printer discovery no longer produces a High alert
  unless the fake host is actually modeling an IPP printer or receives a
  nonstandard request.
- App timestamps are displayed in local time as `YYYY-MM-DD HH:MM:SS`.

### Safer macOS installation and networking

- The packaged sensor runs as the dedicated `_squirrelops` account and uses a
  narrowly authorized root helper for network changes.
- Virtual IPs use isolated loopback /32 bindings, scoped proxy ARP, and guarded
  packet-filter rules so a fake address cannot expose unrelated ports on the
  sensor Mac.
- Package upgrades preserve the database and configuration while validating
  helper readiness, runtime ownership, dependency locks, and installed
  versions.
- Release automation now fails closed unless the installer is signed,
  notarized, stapled, and accepted by Gatekeeper.

### Known platform boundary

macOS proxy ARP cannot give each fake host a distinct physical MAC address, and
some reverse-DNS clients may still report the sensor Mac's hostname. Distinct
Layer 2 identities require a VM or virtual-Ethernet architecture.
