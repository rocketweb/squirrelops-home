## What is new in SquirrelOps Home 2.0.2

SquirrelOps Home 2.0.2 validates and remediates the actionable findings from
the August 10 security review.

### Security hardening

- Configuration credentials now persist in the encrypted secret store instead
  of runtime YAML. Existing plaintext Home Assistant, LLM, and webhook secrets
  migrate and are scrubbed at startup.
- Push relay and device tokens are redacted from both configuration endpoints,
  encrypted at rest, and preserved by partial Settings updates. Unrecognized
  alert-method fields now fail closed instead of being returned verbatim.
- Switching LLM providers cannot reuse a redaction marker to send the previous
  provider's credential to a custom endpoint.
- Updated alerts that are already resolved, dismissed, or actioned no longer
  generate a second notification.
- Update checks run only after an explicit click, select published `home-v*`
  releases, and accept links only for the expected GitHub repository and tag.
  Independent app and sensor versions are no longer compared to a Home release.
- Sensor-only releases are prevented from becoming the repository's Latest
  release, and the live macOS QA checks no longer require GNU `timeout`.
- Production runtime guards no longer depend on Python `assert` behavior.
- Decoy credential selection uses cryptographically secure randomness.
- Python system tools resolve through fixed absolute path candidates.
- The dormant plugin loader rejects traversal, links, writable paths, and
  untrusted file owners.
- Configuration writes are rate-limited per paired identity and create
  value-free audit events.
- New TLS server certificates no longer claim `0.0.0.0` as an identity.
  Existing affected server certificates rotate under the installation CA.
- The production dependency lock now uses patched `aiohttp` 3.14.3 and
  `cryptography` 50.0.0 releases.

### Local test package

The package builder supports an explicit ad-hoc local test mode. The resulting
package is for local installation only. It is not a signed, notarized, or
publishable release artifact, and release mode rejects this flag.

### Intentional boundaries

The macOS processes remain outside App Sandbox because the app and privileged
helper require system LaunchDaemon, Unix socket, and network-control access.
Signed builds still use Hardened Runtime and keep library validation enabled.
The LAN API continues to use mutual TLS, and self-signed-device probes remain
credential-free, target-constrained, redirect-free, proxy-free, and bounded.
