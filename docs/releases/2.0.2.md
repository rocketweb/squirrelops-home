## What is new in SquirrelOps Home 2.0.2

SquirrelOps Home 2.0.2 validates and remediates the actionable findings from
the August 10 security review.

### Security hardening

- Configuration credentials now persist in the encrypted secret store instead
  of runtime YAML. Existing plaintext Home Assistant, LLM, and webhook secrets
  in the runtime `config.yaml` written by the API migrate into the store and
  are scrubbed from that file at startup. Credentials you supply through a
  base config file or a `SQUIRRELOPS_*` environment variable stay where you
  put them: the sensor reads and re-encrypts them, but it does not rewrite a
  file it does not own.
- The macOS app no longer lets any sensor response reach the disk, and an
  upgrade purges the response cache earlier versions wrote. Releases before
  2.0.2 cached `GET /config` bodies unencrypted under the app's Caches
  directory. Clearing that cache removes the stored copy but cannot undo a
  disclosure, so rotate any Home Assistant token, Slack webhook URL, or
  classifier API key that was configured before upgrading.
- Push relay and device tokens are redacted from both configuration endpoints,
  encrypted at rest, and preserved by partial Settings updates. Unrecognized
  alert-method fields now fail closed instead of being returned verbatim.
- Switching LLM providers cannot reuse a redaction marker to send the previous
  provider's credential to a custom endpoint.
- Updated alerts that are already resolved, dismissed, or actioned no longer
  generate a second notification. Closing an alert also clears its bounded
  notification baseline so a later reactivation can notify again.
- Update checks run only after an explicit click, select published `home-v*`
  releases, and accept links only for the expected GitHub repository and tag.
  Malformed individual release records are ignored without suppressing valid
  Home releases. Independent app and sensor versions are no longer compared to
  a Home release.
- Sensor-only releases are prevented from becoming the repository's Latest
  release, and the live macOS QA checks no longer require GNU `timeout`.
- Production runtime guards no longer depend on Python `assert` behavior.
- Decoy credential selection uses cryptographically secure randomness.
- Python system tools resolve through fixed absolute path candidates. A
  selected executable must be a root-owned, non-writable regular file, and
  every directory on its path must be root-owned and non-writable. Symlink
  chains are resolved rather than refused, so the packaged Linux layout through
  `/etc/alternatives` is accepted while a name that launders a target out of a
  writable directory is not. An absent tool still fails with a missing-file
  error instead of falling back to `PATH`.
- A tool that is present but untrusted is no longer reported as an ordinary
  failure. Paths that execute as root refuse and raise; best-effort interface
  probes still degrade to an empty result but log the refusal rather than
  hiding it at debug level.
- The dormant plugin loader rejects traversal, links, writable paths, and
  untrusted file owners. Optional bulk discovery skips unsafe paths while
  explicit loads remain strict.
- Configuration writes, including empty updates, are rate-limited per paired
  identity and create value-free audit events. Expired limiter identities are
  pruned and the identity cache is bounded.
- New TLS server certificates no longer claim `0.0.0.0` as an identity.
  Existing affected server certificates rotate under the installation CA.
- The production dependency lock now uses patched `aiohttp` 3.14.3 and
  `cryptography` 50.0.0 releases.

### Local test package

The package builder supports an explicit ad-hoc local test mode. The resulting
package is for local installation only. It is not a signed, notarized, or
publishable release artifact, and release mode rejects this flag.

Installing a local-test package also requires a one-time administrator opt-in
on the target Mac:

```bash
sudo /usr/bin/install -o root -g wheel -m 600 /dev/null \
  /var/db/com.squirrelops.allow-local-test
sudo /usr/sbin/installer -pkg SquirrelOpsHome-2.0.2.pkg -target /
```

The installer validates that the opt-in is a root-owned, mode `0600` regular
file without an extended ACL, then consumes it immediately, before any install
step runs. The token authorizes one attempt, not one success: if the install
fails partway, the opt-in is already spent and a retry needs a fresh one. That
ordering is deliberate, because consuming it only at the end left it armed for
an install the operator never authorized after any earlier failure.

### Intentional boundaries

The macOS processes remain outside App Sandbox because the app and privileged
helper require system LaunchDaemon, Unix socket, and network-control access.
Signed builds still use Hardened Runtime and keep library validation enabled.
The LAN API continues to use mutual TLS, and self-signed-device probes remain
credential-free, target-constrained, redirect-free, proxy-free, and bounded.
