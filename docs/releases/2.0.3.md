## What is new in SquirrelOps Home 2.0.3

SquirrelOps Home 2.0.3 removes the setup key and Terminal step from normal
setup when the sensor runs on the same Mac. Remote sensors still use the
existing pairing flow.

### Build Local Sensor

- The signed macOS package includes the app, sensor runtime, and privileged
  helper. macOS Installer asks for one administrator approval for the complete
  local installation.
- On first launch, choose **Build Local Sensor**. The app detects the packaged
  sensor and enrolls automatically. It does not ask for another password or a
  setup key.
- First-launch setup now uses a compact, task-sized window. While the local
  sensor starts, **Connect to Another Sensor** remains visible as a bordered
  button instead of looking like status text.
- The app creates its private key in macOS Keychain. The key never leaves
  Keychain. The sensor activates the pairing only after the app proves it owns
  that key over mutual TLS.
- The app, unprivileged `_squirrelops` sensor, and root helper remain separate
  processes. Closing the app does not stop protection, and the sensor continues
  across login sessions and restarts.

### Connect to Another Sensor

- The standalone app remains available for sensors running elsewhere on the
  network. It installs no local services and does not request administrator
  approval.
- Choose **Connect to Another Sensor**, select the sensor discovered through
  mDNS, and enter its one-time setup key. Certificate storage, mutual TLS, and
  authenticated WebSocket connections are unchanged.

### Upgrades and recovery

- Existing packaged installations enable automatic local enrollment during
  upgrade unless the operator explicitly set `local_enrollment_enabled: false`.
- The upgrade migration preserves existing pairing settings, including
  one-line flow-style YAML, and fails closed if any existing configuration
  value would change.
- Installer now verifies a stable launchd handoff instead of waiting for every
  persisted mimic to finish restoring. This removes the multi-minute "less
  than a minute" stall and avoids macOS terminating an otherwise healthy
  package script at its fixed runtime limit.
- Conflict-safe mimic restoration continues under the sensor service after an
  upgrade. The app reconnects automatically when the authenticated API is
  ready.
- Build Local Sensor now retries the starting sensor every three seconds for up
  to 20 minutes. It shows exact elapsed time and does not replace a normal
  decoy-heavy upgrade with a Sensor Not Responding error after one retry.
- Each explicit ad-hoc local-test package uses an isolated Keychain namespace.
  Rebuilding the test app no longer causes repeated password prompts for
  private keys protected for an earlier ad-hoc signature. Signed releases keep
  their stable production Keychain namespace.
- Lost enrollment responses and confirmations can be retried without issuing a
  second certificate or activating the wrong key.
- **Use Setup Key** remains available as a recovery path when automatic local
  enrollment cannot finish.

### Help

- The macOS Help menu now includes direct navigation to every section in the
  built-in guide. Selecting a topic opens or activates the Help window with
  that section selected.

### Security boundaries

- The helper enrollment service accepts only the signed SquirrelOps Home app
  running as the current console user. It exposes no privileged network RPCs to
  the desktop app.
- Explicit local-test packages bind helper enrollment to the exact code hash of
  the root-owned installed app. Production packages continue to require the
  SquirrelOps Developer ID Team ID and Apple signing anchor.
- The helper forwards one bounded certificate request to a root-only sensor
  socket. There is no local enrollment HTTP endpoint and no enrollment listener
  on the LAN.
- A new certificate remains pending and cannot authenticate normal API or
  WebSocket requests until its matching private key completes the mutual TLS
  confirmation.
- Failed post-move validation now removes the unverified helper or launchd
  plist instead of leaving a privileged artifact behind after Installer exits.
- Mimic overload cleanup now releases per-connection bookkeeping even if the
  operating system reports an unexpected stream-close error. Byte-exact
  regression checks confirm this internal fix does not change attacker-visible
  HTTP, 404, or banner responses.
