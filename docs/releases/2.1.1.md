## What is new in SquirrelOps Home 2.1.1

Home 2.1.1 recovers the 2.1 release build after dependency drift stopped the
unpublished Home 2.1.0 candidate. The app remains 2.1.0; the embedded sensor is
2.1.1. Existing 2.1.0 component and distribution tags are unchanged.

### Source and notice packaging

- The installer includes project terms and consolidated third-party notices.
  A checksummed and attested source companion accompanies the release, covering
  the full guest package inventory, including inherited Alpine base packages,
  and exact installed Python source distributions.
- Native Python dependency notices come from the exact standalone Python build.
- Scapy remains a Linux dependency and is no longer bundled on macOS, where it
  is unused. Other runtime dependency versions and decoy behavior are unchanged.
- The product license remains PolyForm Noncommercial 1.0.0. Third-party
  components retain their own licenses. See [distribution notes](../THIRD_PARTY.md).

### Reproducible guest package inputs

- Guest builds use retained, checksum-pinned Alpine packages instead of resolving
  dependencies from live repositories. Alpine signature checks and the complete
  installed-package inventory check remain required.
- Clean builds install packages with networking disabled. Both guest
  architectures must build before the required supply-chain check can pass.
- The reviewed snapshot updates 11 dependencies, including the isolated guest's
  Linux kernel. OpenSSH and Samba versions, persona files, and protocol settings
  are unchanged. The guest remains memory-only with no network adapter.
- This is an Apple Silicon macOS distribution, not an Intel Mac or Linux release.

The rest of the 2.1 feature set follows.


SquirrelOps Home 2.1 adds a coherent deep decoy for Apple Silicon (ARM64)
Macs. It presents one forgotten build Mac named `studio-mini.local`, with a
single synthetic history shared by every protocol and file.

The app and native sensor require macOS 14 (Sonoma) or later on Apple Silicon.
Intel Macs are not supported.

### A real build Mac target

- SSH is served by OpenSSH and SMB by Samba inside a disposable guest. Finder,
  command-line clients, and scanners negotiate the real protocols rather than
  a banner or HTTP approximation.
- The guest includes writable `Builds`, `Engineering`, and Time Machine shares,
  plus an authenticated `buildbot` shell, SFTP, a small Swift project, build
  logs, shell history, agent configuration, and synthetic credentials.
- Ollama, OpenAI-compatible, and MCP endpoints describe the same project,
  models, deployment names, runbooks, and credentials. Their source-specific
  narrative advances as a visitor browses, searches for secrets, invokes
  tools, or performs write-like operations.
- The Decoys screen groups all five services under one Studio Build Mac. One
  control starts or stops the complete host, and a missing runtime, invalid
  guest, or failed Bonjour registration is shown as degraded.
- OpenAI-compatible chat supports SSE streaming, and Ollama chat supports
  NDJSON streaming by default. Explicit non-streaming responses retain the
  same synthetic narrative.
- Studio startup diagnostics are visible even if no host card could be created.
  Enabled, unavailable hosts retry on later network scans with a one-minute
  minimum interval. Repeated startup does not create duplicate guests, and
  intentionally stopped hosts, including degraded ones, stay stopped.
- Ordinary File Share SSH-key bait is parseable RSA PEM. Invalid legacy bait is
  replaced for serving on restart while retaining original credential history.

### Isolation and evidence

- OpenSSH and Samba run inside a fresh memory-only Virtualization.framework
  guest with no network adapter, host share, clipboard, disk image, camera,
  microphone, or graphics device.
- Only fixed Virtio socket channels exist. The separately signed runtime relays
  opaque SSH and SMB bytes and reports bounded connection metadata. It does not
  parse either protocol.
- Relay sockets stay owned until both transfer directions finish. Closing a
  client's write side no longer truncates a response still arriving from the
  guest. Oversized internal telemetry records are discarded without stopping
  collection of later connection evidence.
- Stalled relay cleanup preserves active transfers: five minutes without byte
  progress, or 30 seconds without progress after a half-close. Guest connection
  setup has a 10-second deadline and closes late callbacks safely.
- SSH scans no longer penalize the shared guest loopback address for every
  visitor. The existing 16-connection host ceiling is unchanged.
- Alert details distinguish guest connections from capacity rejection and
  connection failures. Rejected attempts remain visible decoy hits.
- The persona archive is generated in memory for each boot. It contains only
  synthetic data and install-specific fake secrets derived from an encrypted
  local seed.
- Source address, service, inferred intent, narrative stage, and interaction
  type are retained with decoy evidence. No response directs a visitor to real
  infrastructure.
- Repeated connections from one source remain one active alert to avoid a
  notification storm, but the app now shows the folded connection total,
  per-service counts, first and last seen times, and a recent connection
  timeline. Single-service activity is labeled Decoy Activity; two or more
  services promote the alert to Port Scan Detected.

The Decoys screen hides routine Studio status and shows notes only during
startup or when attention is needed. Pull-to-refresh reloads both the list and
status, including an empty list; Command-R and a context-menu action remain
available without a permanent Refresh button.
The pull threshold follows visible list movement, so accelerated trackpad
input alone does not trigger a refresh on macOS 27.
Successful manual refreshes now show a brief **Updated just now** confirmation,
including when the returned data is unchanged. It disappears after three
seconds, supports VoiceOver announcements, and respects Reduce Motion.

Decoy lifecycle switches now have spoken names identifying their fake host or
listener. Detail links retain their service/address labels and support keyboard
activation, Escape dismissal, and focus return with macOS Keyboard navigation
enabled. Local app builds resolve Swift's output path from the selected
toolchain and support an explicit SDK, avoiding stale output-directory
assumptions on macOS 27.

### Desktop usability

- The dashboard network map includes current device types such as smartphones,
  NAS devices and network equipment. Older category names remain supported,
  and unrecognized types stay visible under Unknown instead of disappearing.
- AI settings can discover models into a searchable native picker and test the
  selected model from the sensor. Tests use synthetic classification and naming
  requests, show elapsed time and actionable failures, and never send real
  device data. Manual model IDs remain available when discovery is unsupported.
- Credential filename help now distinguishes HTTP File Share decoys from
  Studio Build Mac's separate SMB and SSH persona files.

- Compact, consistent page headers leave more room for content. Device view,
  sorting, grouping, and search remain usable at the minimum window size.
- Alert severity and type filters use native menus. History, export, bulk
  dismissal, and clearing history are grouped under Actions; destructive
  history clearing still requires confirmation.
- Settings groups share a readable width while inventories and decoy grids
  continue using the available window space.
- Status and supporting text adapt to light and dark backgrounds. Long names
  have hover help, compact device rows retain full IP and MAC addresses, and
  decoy cards include an explicit View Details action.
- An alert detail that cannot load offers Try Again and Close, including
  Escape to close, instead of leaving a dead-end sheet.

### Release integrity

- Guest builds no longer inherit Docker's hostname and DNS settings. Studio's
  hostname resolves inside the isolated guest, removing the repeated DNS
  timeouts observed during SMB negotiation and authentication. Packaging checks
  reject builder settings even when the archive's checksum is valid. The guest
  still has no network adapter or external DNS access.
- Sensor shutdown now runs asynchronous guest and network cleanup before
  the web server re-raises SIGTERM or SIGINT. Previously, signal replay could
  skip or interrupt cleanup and leave the guest running after the sensor exited.
- The sensor has an explicit 60-second launchd shutdown allowance. Package
  upgrade and uninstall checks allow for that interval before reporting a
  stop failure. On systems with a five-second default, macOS could otherwise
  force-stop the sensor before it reached guest cleanup.
- Classic listeners now manage only their own decoy types. Startup, upgrades,
  profile limits, and recovery no longer stop Studio services or try to start
  them as HTTP file shares. Intentionally stopped hosts remain stopped; this
  fix does not automatically repair stopped rows from earlier test builds.
- Pairing stops if secure nonce generation fails. Remote pairing and local
  enrollment share client-name validation, and malformed control WebSocket
  messages are rejected without crashing the handler.
- Connection-anomaly alerts match exact destinations, so an existing alert
  for one address or port cannot suppress another through a substring match.
  Invalid AI classification fields are rejected before downstream use.
- macOS 27 recovery candidates handle the system SQLite backup behavior and
  the package builder's omitted bundle-relocation key while retaining backup
  verification and explicit non-relocatable installation.
- Installer cleanup accepts the existing `_squirrelops` service account's two
  known display names and handles macOS reporting a missing group attribute
  with a successful exit status. Account identity, membership, non-login shell
  and home-directory checks remain in place; unexpected responses still stop
  cleanup.
- When a VPN owns the default route, the macOS helper verifies a physical LAN
  using network service order. Sensor discovery, allocation, and advertising
  use that same LAN. Privileged mutations still recheck the selected route,
  subnet, alias ownership, listener ownership, and packet-filter isolation.
- Local MAC ownership is observed through the authenticated macOS helper,
  avoiding privacy-redacted Python interface identities that could cause the
  sensor to evacuate its own mimics. Classic listeners stay on the selected
  physical interface even when the VPN owns the default route.
- New virtual-host allocation reserves every unretired host address, including
  stopped Studio hosts, without deleting history or weakening address uniqueness.

- The ARM64 app, signed guest runtime, ARM64 kernel, and memory-only
  initramfs are built and verified as one release boundary.
- Guest resources, containment settings, service ports, file set, architecture,
  and SHA-256 digests are checked before packaging and again at runtime.
- Release automation builds the guest from an exact Alpine 3.24.1 image digest.
  Missing, writable, linked, malformed, oversized, or mismatched artifacts fail
  closed and publish no real-protocol ports.

Full VNC is intentionally outside 2.1. It remains a future guest surface after
SSH and SMB complete the cross-device deception review.

The Studio persona runs on an isolated Linux guest with macOS-shaped files and
commands. It is not full macOS virtualization, and detailed operating-system
fingerprinting can identify the underlying guest.
